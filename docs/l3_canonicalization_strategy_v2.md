# L3 Canonicalization Strategy v2

## Objective of This Step
- Convert noisy bottom-up L3 candidates into a human-reviewable canonical shortlist per `l1 > l2` bucket.
- Keep this step strictly additive: shortlist generation only, no taxonomy overwrite and no topic reassignment.

## Inputs and Scope Boundaries
- Inputs:
  - `human-in-the-loop/l3_candidate_bank_v2.json`
  - `human-in-the-loop/topic_taxonomy_view_v2_part1.json`
  - `human-in-the-loop/topic_taxonomy_view_v2_part2.json`
- Non-goals:
  - no edits to old production scripts/UI/JSON
  - no edits to `config/topic_taxonomy_v2.yaml`
  - no final L3 assignment pass

## Canonicalization Pipeline
- Stage 1: normalize labels (`snake_case`, lowercase ASCII, deterministic token cleanup).
- Stage 2: reject noise (stop-like words, question scaffolding, malformed fragments, over-specific prompt artifacts).
- Stage 3: merge aliases/near-duplicates into reusable canonical concepts.
- Stage 4: aggregate evidence at canonical-label level (support, merged raw labels, representative examples).
- Stage 5: rank and trim to bucket-level shortlist size suitable for human decision.

## Deterministic Rejection Rules
- Remove function/scaffolding labels (e.g. `other`, `any`, `thing`, `someone`, `often`, `more`, `less`).
- Remove malformed labels:
  - labels with obvious prompt/question artifacts
  - labels that are too long or too specific to one prompt
  - labels with low semantic portability
- Remove verb-fragment noise when a stable noun concept exists.

## Deterministic Merge Rules
- Alias and near-duplicate consolidation is rule-based and repeatable.
- Examples:
  - `child` / `kid` / `childhood_activity` -> `childhood`
  - `chat` / `chatting` / `conversation` -> `conversation`
  - `shop` / `shopping` / `store_visit` -> `shopping`
  - `exercise` / `sports` / `walking` -> `exercise` (bucket-dependent)

## Evidence Preservation Rules
- Each proposed canonical label keeps:
  - `support_count`
  - `merged_from_raw_labels[]`
  - `representative_topics[]`
  - `representative_question_snippets[]`
  - `confidence`
- Confidence is deterministic from support strength and merge consistency.

## Bucket-Level Shortlist Policy
- Output is generated by bucket (`l1 > l2`), not by topic.
- Target shortlist size: usually 5-15 labels per `l2` bucket.
- Narrow buckets may keep fewer labels when only a small stable concept set exists.

## Human Decision Layer
- Review output includes per-bucket recommendation status:
  - `APPROVE`
  - `APPROVE WITH TRIM`
  - `NEEDS MANUAL SPLIT`
  - `NEEDS MANUAL REBUCKET`
- Rejected-noise examples are surfaced explicitly to speed manual governance.

## Priority Buckets for Tight Review
- `place > outdoor`
- `experience_activity > routines`
- `object > tangible`
- `abstract_concepts > communication`
- `people > close_bonds`

## Exit Criteria for This Step
- Canonical shortlist artifacts are generated and human-readable.
- No production behavior is changed.
- Outputs are ready for later governance to update canonical taxonomy in a controlled follow-up step.
